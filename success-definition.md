## Notes on scope

- **Pushing is split between two places, so two rows cover it.** The source says the library
  never pushes (FS-12) and the merge contract does the push with a plain `git push` (FS-13).
  A fixture run of the library alone therefore never shows a push; the push itself is proven
  from the contract and its jest suite.
- **Not written as a criterion: what happens to the in-progress merge on the two-attempt
  stop.** Objective O2 says the merge is "left for hand repair" on that path, but the source
  says only that `check` returns `stop` with the STUCK text; it does not say whether the
  merge is kept or aborted there. FS-9 checks that nothing is committed, and FS-12 that
  nothing is pushed; whether `MERGE_HEAD` survives is left out rather than guessed. The
  exerciser should record which it observed.
- **Not written as a criterion: how `merge-up.js decide` hands over to this library.** O1 opens
  with "when merge-up.js decide says merge-in"; the source does not mention `merge-up.js`, so
  no row claims anything about that hand-over beyond the seam case in FS-22.
- **Not written as a criterion: which lint, typecheck and test commands count as "affected".**
  The source names the three kinds of check and the `--trd <path|none>` argument but not how
  the commands or the affected tests are chosen, so FS-7 asks only that each kind ran and
  passed.
- **Not written as a criterion: `docs/guides/ship-build.md`.** The source lists it as touched
  but states nothing it must say.
- **"Well-formed" STUCK is read as "the text `stuckText` produces".** Its format belongs to the
  predecessor feature (conflict classifier and stop rules); FS-14 and FS-15 check this
  feature's output against it rather than restating that format.
