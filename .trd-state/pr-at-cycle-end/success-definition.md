## How to exercise these (applies to every row)

The `mode`/`ensure` rows (FS-1 to FS-19) are exercised against the CLI `node <repo>/packages/core/lib/pull-request.js` (the vendored copy at `.claude/lib/pull-request.js` is equivalent). The CLI runs **only against isolated inputs**:

- a throwaway git repo in the scratchpad with its own `.claude/settings.json`, and a **local bare repo as `origin`**. Never this repository's real remote;
- a **stub `gh` first on `PATH`** that appends its argv to a log file and answers from fixtures (`repo view`, `pr list`, `pr create`, `auth status`). A real `gh` is never called;
- `cwd` set to the temp repo, with `GIT_DIR` and `GIT_WORK_TREE` unset.

Rows FS-20 to FS-30 are static checks (`jq`, `grep`, `wc -c`) on files in this repository, or a `scaffold-project.sh` run against a temp project. No row requires a `claude` session or a smoke test.

**Limit, stated up front:** FS-23 to FS-28 check that the `/audit-build`, `/close-feature` and `/implement-trd` prompts *contain* the instruction. They do not prove that a live command run follows it. Proving that needs a `claude` session, which this verification excludes. Treat a pass on those rows as "the instruction is written", not "the command behaves".
