# Sweep batch — 2026-10-01

Recorded findings from the pr-at-cycle-end and never-unattended-paths builds, plus the
findings log's missing "fixed" state. Each is small and independent; each says what's wrong,
where, and the fix. Every packages/core change is mirrored to its .claude/ copy byte for byte
(packages/full/lib entries are symlinks). NEVER run a real `gh`, touch the real remote, or run
smoke tests or `claude` sessions.

1. The PR step opens a PR from whatever branch is checked out. `/close-feature` and
   `/audit-build` call `node .claude/lib/pull-request.js ensure` without saying which branch the
   feature lives on, so run on the wrong branch they push it and open a PR titled after the
   wrong feature. Fix: add an optional `--expect-branch <branch>` to `ensure`
   (`packages/core/lib/pull-request.js:75`, `main` at :111). When given and it differs from the
   current branch, return `skipped` with a reason naming both branches, before any push. Pass
   it from `packages/core/commands/audit-build.md` ("Open the pull request") and
   `packages/core/commands/close-feature.md`, using the `branch` recorded in
   `.trd-state/<feature>/implement.json` (omit the flag when there is no such record). Add
   Jest tests in `pull-request.test.js` (mismatch -> skipped, no push; match -> proceeds), and
   a command-surface assertion that both commands pass `--expect-branch`.
2. A stale `gh` login on another host makes `ensure` skip. `gh auth status` exits non-zero if
   ANY configured host has a bad token, even when github.com is fine, so `ensure` reports
   "gh missing or not authenticated". Fix: check the host the remote actually uses, e.g.
   `gh auth status --hostname <host>` with the host parsed from `git remote get-url origin`
   (default `github.com` when it can't be parsed). Add a test with a stub `gh` that fails
   plain `auth status` but passes `--hostname github.com`.
3. `discovered.promoteToTrd` writes garbled TRD rows for gap discoveries
   (`packages/core/lib/discovered.js:287-301`). The acceptance criterion is built as
   `<summary> no longer reproduces: <evidence>`, which puts the gap's evidence (the proof it
   EXISTS) where the pass condition belongs, and the Serves cell says "amendment — no objective
   recorded" even when the summary names one (e.g. "(O3)"). Fix: for `kind: gap`, write an
   acceptance criterion that is checkable when the gap is closed (e.g. "<summary> — done, and a
   test fails if it is undone"), and leave the evidence out of it; for `bug`, keep "no longer
   reproduces" but without appending the evidence; take Serves from an objective id named in
   the summary (`O\d+`) when present. Update its tests.
4. Two holes in the never-unattended check (`check-never-unattended`,
   `packages/core/lib/functional-verification.js` ~:1530-1560, `readNeverUnattended`):
   (a) touched files come only from grounding blocks, so a task with no grounding (or an
   unbolded Touches line) adds no files and the brake passes silently. Fix: when any task has
   no grounding touches, return `status: 'invalid'` with a reason naming the task(s), so
   `/plan` stops rather than building unchecked. (b) A bullet with a trailing note
   (`- auth — login code`) keeps the note in the fragment, so it never matches. Fix: cut a bullet
   at the first ` — `, ` - ` or ` #` followed by text, and say so in the template's §5b text
   (`packages/core/templates/claude-directory/rules/verification.md` — the template only; never
   edit `.claude/rules/verification.md` directly except to keep it byte-identical to the template,
   which the runtime-integrity test requires). Tests for both.
5. `fix-plan.js` and `plan.md` disagree on the route to `/create-prd`. `plan()`'s `route: 'prd'`
   branch (`packages/core/lib/fix-plan.js:85-95`) still returns `banner: null`, `notify: false`,
   while `plan.md` ("Route: 'prd' — the feature exit") dispatches `Workflow(create-prd)`, which
   prints no banner, and has `/plan` print its own banner and fire notify. `plan.md` even says
   these literals describe the old mechanism. Fix: make the lib return the banner and
   `notify: true` for that route, update `fix-plan.test.js`, and remove `plan.md`'s paragraph
   explaining the mismatch.
6. The findings log has no "fixed" state. `discovered.js` (`record` at :453; `readAll`/`render`)
   has no way to mark a record resolved, so findings a sweep or build already fixed keep
   appearing as open (e.g. most of `.trd-state/_sweep/discovered.jsonl`). Fix: add
   `resolve(stateDir, match, { by, note })`, which appends a resolution record (append-only,
   like the rest of the log) keyed to the original record's id or exact summary; make
   `readAll` take `{ open: true }` to drop resolved records, and have `render` and
   `promoteToTrd` skip resolved ones. Add a CLI or one-liner usage note in the module header.
   Tests. Then use it to mark resolved the records in `.trd-state/_sweep`,
   `.trd-state/pr-at-cycle-end` and `.trd-state/never-unattended-paths` that are already fixed
   (sweep items fixed in PR #15, the never-unattended brake in PR #16, the three AMEND test
   gaps), plus whichever of items 1-5 this sweep fixes.
