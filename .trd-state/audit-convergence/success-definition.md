## How to read this definition

- **Two kinds of evidence.** Behaviour in `audit-rounds.js` (the round-ledger library, `packages/core/lib/audit-rounds.js`, vendored to `.claude/lib/audit-rounds.js`) and in the promotion of discoveries to TRD rows is checkable by running it: `node .claude/lib/audit-rounds.js ...`, a `node -e` call, or Jest, each against an **isolated temp directory**, with its output captured to a file. Behaviour that lives only in command prompts (`audit-build.md`, `implement-trd.md`) or in the prompt text inside the `audit-build.js` workflow can only be checked **as prompt text** — the artifact is the file itself and the locator is the instruction found in it. A prompt-text row proves the instruction is written down, not that a live run obeys it; that limit is stated here so nobody reads a `met` on such a row as more than that.
- **No live sessions.** No row requires running a `claude` session, a smoke test, real `gh`, or touching the real remote. Rows about opening a PR are prompt-text rows for that reason.
- **"Re-audits used" and the cap.** The source states the cap as "2 re-audits used" (L23–L24) and the readout as "round 2 of at most 3" (L31). Read together: round 1 is the original audit; rounds 2 and 3 are the two re-audits; a round that still finds defects at round 3 closes with a caveat instead of re-auditing again. FS-17 checks the whole sequence so the result does not depend on how `decide` counts its `rounds` argument.
- **Exact names are targets.** Where the source names a CLI subcommand (`stale-wake`, L36) the evidence uses it; where it does not (the `classify` and `decide` entry points), the exerciser may call the exported function instead. The check names "citation" and "consistency" (L14) are whatever ids `audit-build.js` gives those two checks.
- **Every row is `locator`.** Nothing here is pictorial; every artifact is text.
