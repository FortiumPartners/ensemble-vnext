## How to read this definition

- **The rulings win.** The source says the owner rulings (L43–L45) supersede anything in the intended change that disagrees with them. Where a row's `Cites` reads "Lxx superseded by Ruling n", the row states the ruling's behaviour, not the earlier line's. The three supersessions that matter: at the re-audit cap the feature stays **open** and NEXT is the owner's call (Ruling 1 replaces L24's "close with a caveat"); a finding from the test-quality check is always a **test gap**, and a weak test that masks a defect is reported as that defect by the check that owns it (Ruling 2); a re-audit checks **only** the previous round's defects and the code changed since that audit, takes no fresh sample, and records anything else as a non-blocking discovery (Ruling 3 narrows L34's "first").
- **Two kinds of evidence.** Behaviour in the round-ledger library (`packages/core/lib/audit-rounds.js`, vendored to `.claude/lib/audit-rounds.js`; CLI usage `audit-rounds.js tally|decide|classify|stale-wake|record|trd-hash [json]`) and in the promotion of discoveries to TRD rows is checkable by **running** it — `node .claude/lib/audit-rounds.js <subcommand> '<json>'`, a `node -e` call, or Jest — against an **isolated temp directory**, with output captured to a file. Behaviour that lives only in command prompts (`audit-build.md`, `implement-trd.md`) or in prompt/schema text inside the `audit-build.js` workflow is checkable only **as text**: the artifact is the file itself and the locator is the instruction found in it. A text row proves the instruction is written down, not that a live run obeys it; read a `met` on such a row as no more than that.
- **No live sessions.** No row requires running a `claude` session, a smoke test, real `gh`, or the real remote. Rows about opening a PR or committing are text rows for that reason.
- **The cap.** The source states the cap as "2 re-audits used" (L23–L24) and the readout as "round 2 of at most 3" (L31). Read together: round 1 is the original audit; rounds 2 and 3 are the two re-audits. FS-11 and FS-12 should be exercised as a sequence (rounds recorded into a temp ledger, then `decide`) or with `rounds` set both ways, so the result does not depend on whether `decide` counts `rounds` as audits done or re-audits used. That reading is [inferred] from L23, L24 and L31 together.
- **Where the source is silent, no row asserts.** For example, the source does not say whether a round with both uncovered items and defects re-audits; FS-8 asserts only what L20 says.
