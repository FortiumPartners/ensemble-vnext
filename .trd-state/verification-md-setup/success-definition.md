  one framework-skill list"** (line 65) are about build order and dependencies, not outcomes. If
  that list does not exist, FS-18 and FS-19 fail as not built. They do not become separate
  criteria.
- **"A fixed default floor is rejected"** (Decision line 54–55) is covered by FS-8 and FS-9
  together, since both recommendation paths come from evidence. It has no criterion of its own.
- **Grounding A's byte-identity between this repo's `.claude/rules/verification.md` and the
  template** (line 72–73) describes the current state and an existing test. No objective asks
  for it, so it is not a criterion. The existing `runtime-integrity.test.sh` enforces it.
- **The negative claims are only partly checkable by running the system.** "No autonomous run
  writes `verification.md`" (O3, FS-6) and "prompts only" (FS-1) are statements about
  everything, which a live run cannot demonstrate. Their evidence is a static search of the
  shipped command, workflow and library code. That proves no code path does it. It does not
  prove a model never improvises such a write at runtime.
- **The skill's interview behaviour (FS-2 to FS-5, FS-7 to FS-9) is LLM output**, so a single
  transcript is one sample. Each of those criteria is judged on the run that was captured.
