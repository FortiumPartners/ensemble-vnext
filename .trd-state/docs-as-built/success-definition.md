# Functional Success Definition: docs-as-built

**Source**: docs/PRD/docs-as-built.md (v1.2.3)
**Source kind**: prd
**Derived**: 2026-10-04T23:50:58Z
**Criteria**: 30

Derived from the PRD alone; no TRD, task list or plan was read. How each row can be exercised in
this environment, stated once so the rows stay short:

- **Deterministic library and CLI rows** are proven by a Jest run, or by invoking the module's
  CLI against a fixture git repository built in a temp directory (commits, a `docs/` tree, a
  `.gitignore`, a bare remote where a row needs one).
- **Workflow rows** are proven through the repository's workflow test harness with stubbed
  agents: the stub supplies a score or verdict, and the artifact is the harness's recorded
  dispatches and outputs.
- **Text rows** (the contract file and the `/audit-docs` command prompt) are proven by reading
  the text; the row says so. A text row proves the instruction exists, not that a model follows it.
- **Live-run rows** can only be proven by a headless `/audit-docs` session, which cannot be
  started in this environment; they say so and resolve `not verifiable here`, not as failures.
